现状问题 → 处理

  • ✕
    名称列被裁：QCheckBox 文本与勾选框挤在同一格，5 列均分后每列仅 ~50px 可用宽，"ProxyIP分流1" 必然截断。→ 名称改为固定宽 62px 的组别标签 + 序号，放在第二行左侧，不再和 IP 抢宽度。
  • ✕
    IP / 地区 / ISP 全都被裁：单列 ~50px 放不下 15 字符 IPv4，9 个 32 字符的 IPv6 根本无解。→ IP 独占第一行（等宽字体，478 宽下 32 字符完整显示）；地区 · ISP 移到第二行。
  • ✕
    列表被 2560px 硬编码高度撑开：整页 3281px，滚 3 屏才看得到列表尾巴，表格自身滚动条还被 × AlwaysOff 关掉。→ 去掉 min-height，列表区 flex:1 吃掉剩余高度，内部滚动 + 吸顶表头。
  • ✕
    行高 Stretch + resizeRowsToContents 相互打架：行高随行数变化，50 项时每行 51px、7 项时每行 300px+。→ 行高固定（62 / 紧凑 54 / 单行 46），行数只影响滚动条长度。
  • ✕
    速度列宽度随内容跳动："42ms" / "1204ms" / "连接超时" 混排。→ 固定 86px 右对齐 + tabular-nums，主体只放数字。

设计要点

  1. 两行结构，各字段都有主：第一行 IP（12.5px 等宽）+ 右对齐速度；第二行「组别标签 · 地区 · ISP」。所有行共用同一网格，左边界与右边界逐行对齐。
  2. 表头只留 2 个真标题：原 5 个汉字段（名称/IP/地区/ISP/速度）压成「节点 / 地区 · ISP」「延迟 / 下载」，不再为每个字段留一列。
  3. 3.3 屏 → 1 屏：代理通道压成 1 段选择 + 1 个地址框；6 条线路从 6 行 radio 网格压成 2 行 chip（API / IMG 各一行）；超时、DoH、自定义地区、自定义 IP 收进「高级」抽屉。
  4. 列表永远是最大的一块：标题 + 计数 + 排序 + 分组筛选（全部 / ProxyIP / 优选）一行搞定，剩余高度全部给列表，任何一项都能滚到，不会被裁在外。
  5. 51 项不可能在一屏铺完：按 478×982 算，列表视口约 617px，两行式同屏约 10 项。所以策略是「一屏看全结构 + 列表内滚动看全内容」，配合筛选把 26 / 24 分组减半。
  6. 落到 Qt 的成本：QTableWidget → QListWidget + 自定义 item widget（两个 QLabel，固定 setFixedHeight）；表头 QSS padding: 0 20px 改 0 8px；删掉 min-height 2560、verticalHeader Stretch 与两个 ScrollBarAlwaysOff。
